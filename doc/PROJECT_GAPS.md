# Quantum Agent Platform — 项目不足分析

> 更新时间：2026-07-09

---

## 一、LLM 调用层

| 不足 | 影响 |
|------|------|
| 没有请求重试 | API 超时一次整个任务就挂了 |
| 没有 token 计数 | 不知道一次调用花了多少钱、多少 token |
| 没有响应缓存 | 同样的 prompt 重复调重复花钱 |
| `generate_stream` 不支持 system prompt | 流式和多轮对话不能同时用 |

---

## 二、Agent 核心

| 不足 | 影响 |
|------|------|
| **Planner 没有多轮对话** | 已有 `self.history` 字段但没接入 `plan()` |
| **MCPClient 是 fake 的** | 没有 `subprocess` 调真实工具的能力 |
| **Executor 不支持并行执行** | 如果 plan 里有 3 步互相独立的，也会串行排队跑 |
| **State 没有持久化** | 服务重启后所有进行中的任务全部丢失 |
| **State 没有 timeout** | 一个 Gaussian 任务跑 7 天，Executor 会一直等 |
| **Critic 的 fallback 太粗糙** | 解析失败时靠关键词 `"pass"` 判断，很容易误判 |

---

## 三、LangGraph 工作流

| 不足 | 影响 |
|------|------|
| **只支持"执行一步 → 检查"** | 不能批量执行多步再一起检查 |
| **重试时没把 Critic 的建议传给 Executor** | 重做时不改参数，同样的问题会反复出现 |
| **没有人工审批节点** | 危险操作（如删除文件）没有"等用户确认"的机制 |

---

## 四、RAG 模块

| 不足 | 影响 |
|------|------|
| **Embedder 返回全零向量** | 搜什么都一样，检索形同虚设 |
| **VectorDB 是空壳** | `search()` 永远返回 `[]`，没存没搜 |
| **没有与 Agent 集成** | RAG 模块写好了但 Planner 的 prompt 里完全没用到检索结果 |
| **没有文档管理** | 没有增删改文档的接口，只能一次性 ingest |

---

## 五、FastAPI / Web 层

| 不足 | 影响 |
|------|------|
| **没有用户认证** | 谁都能调 API，公网部署后任何人都能操作你的计算节点 |
| **没有请求限流** | 有人刷 100 个 Gaussian 任务你就破产了 |
| **没有 CORS 配置** | 前端如果部署在别的域名，浏览器会拦截请求 |
| **错误响应不统一** | 有的接口返回 `{"detail":"..."}`，有的返回 `{"error":"..."}`，前端不好处理 |

---

## 六、工程基础设施

| 不足 | 影响 |
|------|------|
| **没有结构化日志** | 全靠 `print()`，出问题没法查、没法统计 |
| **没有集成测试** | `tests/` 下只有手动测试脚本，没有 pytest |
| **配置混在代码里** | `MAX_RETRIES` 既在 `settings.py` 又在 `graph.py` 又硬编码 3 |
| **API Key 还在 .env 里** | 虽然 gitignored 了，但没有任何密钥轮换/过期机制 |

---

## 七、按优先级排序（建议补的顺序）

### P0 — 项目跑不通

- [ ] Embedder + VectorDB 实现 — RAG 现在搜不了
- [ ] MCPClient 接真实工具 — Agent 计算不了

### P1 — 体验很差

- [ ] Planner 多轮对话
- [ ] LLM 请求重试
- [ ] State 持久化 + timeout
- [ ] 结构化日志

### P2 — 不能上线

- [ ] 用户认证
- [ ] 请求限流
- [ ] CORS 配置
- [ ] 错误响应统一

### P3 — 工程化

- [ ] Token 计数 / 成本统计
- [ ] 响应缓存
- [ ] 集成测试 (pytest)
- [ ] 并行执行

---

## 总结

当前项目骨架完整、逻辑链路跑通，但离"能投入使用"还差：

1. RAG 还不能搜（Embedder + VectorDB 空壳）
2. 工具还是 fake（MCPClient 没接 subprocess）
3. 没有错误恢复（LLM 超时、State 丢失）
4. 没有安全防护（认证、限流、CORS）

**好在每个模块的接口设计是对的，补起来不需要重构。**
